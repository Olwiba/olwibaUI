## Usage

Both render as the child of `AuthSection`, so they share its frame and layout.

```tsx
import { AuthSection, AuthCheckEmail, AuthEmailVerified } from "@olwiba/ui";

// After sign-up, while the address is unconfirmed
<AuthSection layout="centered">
  <AuthCheckEmail email={email} onResend={() => resendVerification(email)} signInHref="/sign-in" />
</AuthSection>

// Where the verification link lands
<AuthSection layout="centered">
  <AuthEmailVerified signInHref="/sign-in" />
</AuthSection>
```

`AuthCheckEmail` leads with an **Open Gmail** (or Outlook, Yahoo Mail, iCloud Mail, Proton Mail) button chosen from the address's domain via `inboxLinkFor`. `mailto:` is not used: it opens a new message, not the inbox. An unrecognised domain shows no button. Resending is a quiet link on a cooldown that starts on mount and restarts after each successful resend; throw from `onResend` to report a failure without restarting it.

`AuthEmailVerified` deliberately points at sign-in rather than signing the person in. Verification links usually open inside an email app's own browser, and a session created there leaves the person's real browser signed out.
